# Changelog

## Unreleased

- `goethe run` loads a model that is not loaded on its picker, with a bar beside it, in the first list and in the chat's `m` list, instead of leaving the screen. You can type while a reply streams; Enter sends the line after it. Leaving says nothing and returns at once: a model run loaded is unloaded in the background.
- On a terminal, `goethe install`, `goethe remove`, `goethe load` (and the Install models page) show only the model, progress bars and the result: `Model installed: kernel: ...  ctx: ...  total maximum VRAM: ...`, `Successfully uninstalled`, or for a load the context window, concurrency and VRAM above its bar. Piped output and `--verbose` keep every line; the command log always has them.
- The `goethe run` chat has no export or record any more; Esc then `q` quits at once. A model that was still loading when `goethe run` started is waited for and left loaded.
- The Install models page also uninstalls: Space marks installed models (their dot turns the theme's third color) together with models to install, the screen shows what Enter will install and uninstall, and Enter does both in one go, then shows the table again.
- `goethe login` after `goethe logout` (or a second login) links the same console node again, by a key each install keeps in `GOETHE_HOME/platform/install_key`; `goethe logout` keeps the node on the console, offline, with its settings and analytics. Needs the matching console update.
- `goethe update` no longer prints commit hashes, only versions.
- `goethe uninstall` lists the models (with their total size), inference engines and kernel packs it will delete before asking, also deletes the NInfer weights `goethe install` downloaded to `~/.cache/goethe/nvfp4`, removes only Goethe's card from a folder of your own files, and when something cannot be deleted still removes the rest, names what is left and exits non-zero.
- `goethe run` loads a model that is not loaded yet with a 100,000-token context, or the model's maximum when that is smaller (it is still reduced when the GPU cannot fit it).
- The `goethe run` chat screen labels each message `➤ User` or `➤ Model` in the theme's colors and shows the chat's generated tokens and decode speed on the keys line (not saved, not in the usage log).

## 0.3.5 (2026-11-20)

- `goethe update --check` names nginx by version (from the package's BUILDINFO, which now records it), marks a rebuild of the same wheel or version as "another build", and ends with a summary of what would change.
- `goethe run` without a model opens a list of the installed models to pick from (loaded ones first); a model that is not loaded is loaded for the chat and unloaded after unless `--keep`.
- goethed keeps a local usage log, linked or not: per-model requests by outcome, prompt and generated token counts, latency and time-to-first-token histograms and decode speed, plus 5 s GPU and host samples (utilisation, VRAM, power, temperature, throttling, CPU, RAM, disk), as clock-minute rows for 48 hours and hourly rows for 90 days in `state.db`. Counts and timings only. A linked node sends the new minute rows with its heartbeat (per model, GPU and host; no API keys). See Usage log in `docs/cli.md`.
- The gateway streams every chat, completions, Anthropic messages and Responses request from the engine and rebuilds the reply for a client that did not stream, so time to first token, decode speed and token counts are measured for every request with any engine.
- The menu has a Metrics page below Status (an empty line now separates API keys and gateway from Status): per model and per API key and model the requests, errors, input and output tokens, average time to first token and tok/s and the 95th-percentile latency, then GPU and host use, over 1 h, 24 h, 7 d, this month, 30 d or 90 d. `goethe metrics` opens the same page from the shell (printed once when piped). Every API key is listed, with zeros when it made no request. The API schema example is drawn below the menu, so a copied curl command no longer picks up menu text.

## 0.3.4 (2026-11-19)

- Bundled nginx pin is 1.30.7 (was 1.30.6) for the HTTP/2 fixes (CVE-2026-123007 and related). `goethe doctor` warns when the on-disk nginx is older. Rebuild/republish the package so `goethe update` can refresh the binary.
- `goethe update` refreshes bundled nginx when its signed sha differs, refreshes already-installed engines by default (same as `update engine`), and re-execs `update engine` after a binary swap with the positional form. Kernel-pack fit uses the installed goethe-engine wheel when present (not only the compile-time pin), so a new binary with an old py-env no longer accepts packs it cannot run.
- Docs: `goethe update rollback` (not `--rollback`); `goethe update engine` (not `--engine`).
- `goethe api expose public --yes` without `--allow` no longer binds every interface on a leftover allowlist; name the clients and confirm (`--yes` or `y`). Raw `goethe api expose 0.0.0.0` is refused (use `expose public`). World-open clients need the hidden `--dangerously-allow-all-inbound --yes`.
- The gateway TLS certificate SAN includes this host's interface IPs (tailnet, LAN), so `curl --cacert` to the bind address verifies; the cert refreshes when that list changes.
- `goethe models scan <foldername>` resolves the name under `GOETHE_HOME/models`, not the current working directory.
- goethe picks the engine before downloading: a goethe kernel pack on a logged-in node, else SGLang when it supports the model, else llama.cpp on the repo's GGUF files or on the GGUF build Hugging Face lists for the model (the name typed becomes an alias), else a refusal with each engine's reason. Embedding models like embeddinggemma install this way. On a Mac, llama.cpp with the same GGUF lookup instead of a name search.
- A kernel pack that cannot run gives way to the plain runtime by default, saying why (`GOETHE_ALLOW_FALLBACK=0` restores the error). The pack structure check after a download, and the goethe-engine install it needs, run only when a pack of the model's architecture exists for the GPU.
- `goethe models` shows each model's engine.
- GGUF memory plans count sliding-window and shared-KV layers as llama.cpp allocates them (gemma-4-E2B: 0.8 GB of KV per request instead of 8.8 GB), and a load on a fixed GPU count shrinks the context to fit like any other.
- The menu has Load/Unload under Quick setup: installed models beside it, a load runs in place with its bar next to the model and then says "loaded", and loaded models unload one or several at a time. It is grayed out until a model is installed.
- API keys and gateway has API schema: OpenAI, Anthropic and LiteLLM calls with API_KEY and MODEL_ID placeholders on the gateway's address (VPN, else local, else public). Quick setup ends on the same three schemas.
- q quits goethe from any menu screen and the left arrow goes back; the right arrow opens only what is already shown on the right.
- Install and gateway setup print less: no engine-layer, weights or SGLang-args summary lines, "verifying" instead of a byte count, and "Gateway updated and live" after the gateway changes.
- A load only says it is loading into VRAM until the model is ready. Embedding models warm up with an embedding request, and a chat request to one gets a plain 400 naming /v1/embeddings. SGLang captures CUDA graphs only up to the model's concurrency, which shortens loads.

## 0.3.3 (2026-11-18)

- The installer is one short script for Linux and macOS: it checks the machine, verifies the signed package and `goethe`, and hands over to `goethe setup`, which does the rest and is safe to run again to repair or upgrade. It installs no system packages beyond `openssl` and CA certificates (as root, when missing), no nginx from the distribution (goethe ships its own for Linux too), and no Python environment (the first model install sets it up).
- `goethe doctor --fix` makes the system changes the installer used to make: the NVIDIA driver (load, install, open module for Blackwell), NVIDIA's CUDA 13 forward-compatibility libraries for 535-579 drivers, and a C++ compiler once SGLang is installed, each asked for.
- `GOETHE_VERSION=0.3.3` installs one release; every install reads all its files from one release folder. `goethe.env` keeps only settings that differ from the defaults, and doctor names the line to delete when one breaks the registry. `goethe` and `goethed` are linked onto a folder already on PATH (or PATH is offered for the shell's startup file).
- The command line is regrouped: every action is a word (`goethe api keys create NAME`, `goethe gpu deny gpu2`, `goethe models alias set A M`, `goethe api allow add CIDR`, `goethe api domain check D`, `goethe update engine`), and flags only change how it runs. The older forms are removed rather than kept as hidden aliases; docs/cli.md has the full tree.
- `goethe` alone on a terminal is the entry point: the guided setup while nothing is installed, the home screen after. `goethe start` is gone.
- Network access lives under `goethe api`: `expose` (local, vpn, public, or an address or interface; replaces `api configure` and `api gateway --bind`), `allow` (was `allowlist`), `domain`, and `share` (was `goethe serve --public`; `share stop` closes it).
- `goethe learn` and `goethe trace` are top-level again.
- `goethe status` lists the served models too; `goethe api` is the address, keys and how to connect.
- `goethe load M --save` stores `--gpu`, `--ctx`, `--max-conc` and the engine flags after `--` as the model's defaults (replaces `models config`); `--dry-run` shows the placement without loading (replaces `hw pick-gpus`). `--force` and `--yes` on load are one flag (`--yes`); `--tp` is only for "split over N GPUs goethe picks".
- Extra engine flags are always given after `--` (`--sglang-arg` is gone). `goethe logs goethed|gateway|MODEL`; `goethe doctor --hardware` (was `hw profile`), `--public` (was `--probe-public`); `goethe login --lifetime` (was `token-lifetime`); `goethe remove --traces keep|delete`. Removed: `service`, `get`, `configure`, `logs --prune`, `install --no-load/--no-verify/--reset/--tp`, `--model` and `--gpus` everywhere.

- A model with a kernel pack that cannot open or run on this machine now stops with one reason line and the opt-in (`--fallback`, or `GOETHE_ALLOW_FALLBACK=1`). Nothing silently serves it with llama.cpp or SGLang any more. A model without a pack for this card still uses its plain runtime.
- A pack-only model (Qwen3.8-27B-NVFP4) is refused before any download when the node is logged out or the card is not one its packs are built for.
- A local GGUF folder is offered the kernel pack of the same structure (fine-tunes, Orca): the signed config and tokenizer come with it, the projector file is not taken for the model, and a dropped offer says why.
- `goethe ps` and `goethe models --json` show the serving runtime. A Hugging Face id that does not exist says so instead of "gated".
- Memory overhead learned from earlier loads is kept per serving runtime, so a figure learned under llama.cpp no longer blocks the kernel pack.
- Speech models served by llama.cpp (an audio projector next to the weights) take `goethe run MODEL clip.wav`. `llama-server` comes from the pinned upstream release; the CUDA runtime libraries are fetched only when the host lacks them.
- `goethe update` also refreshes kernel packs of installed models when the index has a newer one: only the blocks the installed pack lacks are fetched, the new pack is verified and swapped in atomically, and the old one is kept for `goethe update rollback`. A running model keeps its pack until reload; `goethe load` says once a day when a newer pack exists.
- `goethe remove` of a local-folder install removes its whole managed folder (never your source folder), and installing the same folder again replaces it. Installing a gated Hugging Face id that is already installed says so instead of asking for a token.
- Security and robustness fixes found by review, each reproduced first: a model repo can no longer write `goethe_card.toml` or `.goethe_*` files into the install (its card could set `LD_PRELOAD`, extra arguments and `--trust-remote-code`); a hostile file listing can no longer point outside the model folder (it made verification delete a file elsewhere); a hostile GGUF header (huge string, layer count or nesting) is refused instead of aborting `goethe install`; kernel-pack byte ranges from a hostile container are checked instead of wrapping; ids that share a folder (`x/y` and `x__y`) no longer take it over from each other; concurrent installs of one model are serialized per id; `install.sh` no longer puts the package token on `curl`'s command line; a symlink named `goethe_card.toml.tmp` in a cloned model folder can no longer make goethe overwrite a file outside the install; temporary files for registry checks and recordings are private and unpredictable (a planted symlink could redirect them onto another file); downloads of package lists, binaries and indexes are size-limited and streamed to disk instead of buffered in memory.
- First-run fixes: Ctrl-C, SIGTERM or a kill of `goethe install` now stops the Hugging Face downloader too (own process group, parent-death signal) and says `interrupted; partial files kept, run the same command to resume`; an unreachable Hugging Face or a dead proxy prints one line (`cannot reach huggingface.co (network or proxy): ...`) instead of a Python traceback, and an install that downloaded nothing leaves no empty model folder; `goethe models` lists gated catalog models marked as needing a token, and the gated message, the list note and `goethe doctor` say the same two ways in (accept the license and use `--hf-token`, or `goethe install DIR --name ID` for weights you already have); `goethe --help` and `goethe start` name the model `goethe models recommend` ranks first for this machine (the smallest catalog model when none fits) instead of a fixed one; `goethe doctor` adds `goethe gpu --deny gpuN keeps a card free for other workloads` when a GPU has foreign processes or little free memory.
- A kernel-pack install checks the per-GPU budget before it downloads a weight: from the model config and the listed size of the weights it computes the plan `goethe load` will use (the pack runtime's own learned figures, never llama.cpp's), prints the fit line with its headroom, and refuses with the card, its free memory and how much is missing when no GPU set fits, instead of failing at load after 20 GB.
- `goethe update` with a build newer than the published release (dev builds, the days before a release) is no longer an error: the version guard belongs to goethe and goethed alone, which are kept with one line (`goethe 0.3.3 is newer than the published 0.3.2; keeping it`) while `update engine` and the kernel-pack refresh go on; `--allow-downgrade` installs the older binaries only when not updating engines alone, so `update engine --allow-downgrade` can no longer overwrite newer binaries. A failed update step no longer skips the kernel-pack refresh.
- The release key is compiled into the binary and is the only trust root for every signature goethe checks; a file in the home or an environment variable can no longer replace it, and a fresh home or source build needs no installer file.
- A pack no allowed GPU can run (its manifest's architecture, SM count or shared memory) is refused before the engine layer or any weight is downloaded, with one line and exit 3.
- Install and load use one memory plan, so the fit line before a download matches the load that follows; a download-only install (`--no-load`) checks the card's total memory, and a busy GPU is named as busy.
- A failed step prints one error line and the path of its log; underlying output goes to `<home>/logs` and shows with `-v`. Long steps print a heartbeat (verifying, starting the engine, loading, warming up) and a pack download that fails transiently is retried.
- CI runs on pull requests into dev and finishes in about three minutes; the full package build runs on main and nightly. `goethe/tests/accept.sh` installs, runs and removes each release model and fails any that is not served by its kernel pack.

## 0.3.0 (2026-11-16)

- `goethe serve --public 5h --key my-app` opens the API on a public address for a limited time (up to 7 days), for chosen existing API keys, which stay the same every time it opens; `goethe serve --public shutdown` closes it early. The public listener exists only while a window is open, accepts only the chosen non-admin keys and only API routes, checks the end time on every request, and has its own certificate and stricter rate limits. A linked node reports the public URL and its end time to the platform within seconds of opening or closing. See `goethe serve --public` in `docs/cli.md`.
- Optimised kernel packs: `goethe install` uses them on nodes logged in to the Goethe platform, asks a node that is not logged in to log in or continue with SGLang, and refuses a model neither can serve before downloading anything. `goethe models` marks models with optimised kernels for this machine.
- New installs default to the model's full context window; a load lowers it when VRAM cannot hold it.
- The installer sets up only a small base Python environment (the `hf` CLI). SGLang and the CUDA libraries (about 8 GB) install once, with the first model that needs them, and goethe-engine with the first kernel pack; both share the one py-env and its hash-locked versions, so the second never reinstalls what the first brought. Existing installs keep their py-env as it is. `goethe update engine` refreshes only the engines that are installed, and `goethe models scan` checks architectures against a bundled list of the pinned SGLang build while SGLang is not installed. After installing, the installer offers `goethe login` on a terminal when the node is not linked.
- `goethe login` links a node to the Goethe platform with a browser login (device code), or without one with `--authkey msh_ak_...` (also an installer flag); `goethe logout` unlinks it. Linking is optional: without it Goethe never contacts the platform. A linked goethed sends a health snapshot every 10 seconds and right after loads and unloads, including the node's API keys for the platform's API table (no engine keys, prompts, paths or command lines), backs off when the platform is unreachable, and stops when the node is revoked. `goethe status` and the home screen show the link and the last heartbeat; `goethe uninstall` logs the node out. See the Platform section of `docs/cli.md`.
- Goethe no longer asks a third party for the public IP: `goethe api configure`, `goethe api domain` and `goethe doctor` ask the Goethe platform's `/api/ip` (`GOETHE_PUBLIC_IP_URL`, `GOETHE_PUBLIC_IP` and `GOETHE_PUBLIC_IP_LOOKUP=0` still work), and a linked node reports the address the platform saw in its last heartbeat.

## 0.2.0 (2026-11-10)

- Tab completion for bash, zsh and fish (`goethe completion install`, `remove`, or the state with no argument): commands and flags, plus installed models (by id, by name in any case, by alias), GPUs, key ids and names, and network interfaces, asked from `goethe` at each Tab. The installer turns it on for your shell (`GOETHE_NO_COMPLETION=1` skips that); `goethe uninstall` removes it.
- Plain `goethe` on a terminal opens a home screen in the same two-column style as the key manager: models (load or unload), API access, keys, GPUs (allow or deny) and learning and traces, each with its state, refreshed every 5 seconds. Actions run the matching command in the normal terminal and come back.
- A leaner command line: `goethe --help` lists 17 commands in the order they are used. API settings moved under `goethe api` (`keys`, `allowlist`, `gateway`, `domain`, `learn`, `trace`) and model housekeeping under `goethe models` (`recommend`, `scan`, `config`, `alias`); `hw`, `gpu` and `doctor` stay separate. The older top-level forms still work, hidden, and say where they moved.
- The model is a plain argument: `goethe load qwen 27b`, `goethe unload qwen-27b`, `goethe install glm flash`. An id, an alias or words from a name; several matches bring up a menu (or are listed without a terminal). `--model` still works. Messages and docs use the new forms.
- `goethe api configure` works with any VPN or private network: it lists the networks this machine is on (tunnels and private addresses; container bridges and public network cards are left out) with the range each reaches, taken from the routing table, and still asks whether to restrict access to specific addresses. Single-device routes widen to their private block, and default routes are never allowed. Before, only Tailscale, WireGuard and ZeroTier names were recognised, and any `100.64.0.0/10` address counted as Tailscale, so clouds and carriers that use that range for NAT could have it all allowlisted.
- The gateway follows the chosen interface instead of a fixed address: a new address is picked up within a few seconds with a hot reload, and while the interface has none it serves this machine only (shown by `goethe status`, `goethe gateway` and `goethe doctor`). `--interface <name>` picks the network without a terminal, and `goethe gateway --bind` takes an interface name too.
- `goethe gpu` redraws every half second instead of every second.
- `goethe api manage`: a full-screen key manager in two columns, like ranger. The left picks the action or key (Create new key, Done, then the keys); the right shows the hovered key's value, name and id, and changes its allowed models (Every model or ticked models), rate limit and expiry, or deletes it after a second Enter. Nothing is written until Save; `q` leaves at once and says what was not saved. On Rate limit and Expires the bottom line shows the values they take. Only changed lines are redrawn, and keys created in the session are printed after the screen closes. Key names must now be 1 to 64 visible characters.
- `goethe configure api` is now `goethe api configure`, in the CLI, its messages and the docs. The old form still works and says so.
- `goethe start`: the advanced setup's key entry opens the key manager (keys made there are listed when it closes); the guided step 3 offers only keys that may call the model just served, so the "Try it" call works, and asks again for an invalid key name; the ready screen points to `goethe api manage`.

## 0.1.8 (2026-11-06)

- `goethe trace on|off [--key ... | --all-keys]` records every chat, Anthropic Messages, completions and Responses request with its reply, for all models and instances, into `~/.goethe/traces` (or `--dir`), as a corpus for training later. Turns are grouped into sessions: follow-ups store only their new messages, and regenerations are kept as alternative replies. Each turn names the exact model version that produced it, and streamed replies are stored in their non-streaming shape. A manifest, a session index and a recording history describe the folder. `off` keeps the chosen keys for the next `on`. `goethe trace` shows the size. Recording turns itself off at a size limit (`--max-gb`, default 20 GB), pauses while the disk is low, and never slows a reply. The format is in `docs/traces.md`; `goethe uninstall` keeps the corpus, and `goethe remove --model` asks whether to delete that model's traces (`--delete-traces`, `--keep-traces`).
- Traces work with any model and client: Responses requests link into sessions and store only new items, including `previous_response_id`; streams keep every field the engine sends, and a cut Responses stream keeps its partial reply. Model fingerprints cover the Goethe version, the runtime, more tokenizer files and single-file checkpoints such as NInfer's. Drop counters survive a restart, goethed writes queued turns before stopping, and a partial write can no longer hide later turns.
- The gateway certificate now has subject alternative names (`localhost`, `127.0.0.1`, `::1`, the hostname and `GOETHE_TLS_NAMES`), so the `curl --cacert` command from `goethe api` verifies. It is regenerated only when those names change.
- `goethe/packaging/Dockerfile` builds a container image with the signed installer.

## 0.1.7 (2026-10-30)

- An RTX 5090 install gets the model that was measured on it: `goethe recommend` lists `meshapplied/Qwen3.8-27B-NVFP4-NInfer` first on a 32 GB Blackwell GPU at ctx 100000 and concurrency 4, `goethe models` lists it too, and `goethe install` curls the pinned `neroued/Qwen3.8-27B-nvfp4-NInfer` file, checks size and sha256, and patches the draft shortlist so tool calls are drafted. Before, the entry was marked as a manual download and recommend hid it.
- Anthropic `thinking.budget_tokens` below 1024 is raised to 1024 at the gateway instead of being rejected; other fields are forwarded untouched.
- `goethe ps` shows a `PREFIX` column from the engine's request log: the share of the last request's prompt that came from the prefix cache. NInfer is started with `--request-log-jsonl` for this.
- Fixes from running 0.1.6 on an RTX 5090: the local NInfer model file is accepted, and `goethe load` no longer starts SGLang for it; the registry JSON is checked against its signature; `goethe recommend` and `goethe models` agree on what fits; VPN mode keeps localhost access; the keyless TCP mode is gone; a `GOETHE_HOME` value can no longer end up in the service unit's ExecStartPost; the load wait mentions kernel builds; the README names a model `goethe recommend` lists.
- Speculative-decoding models on hybrid (linear-attention) architectures load with default settings: memory planning counts the per-draft-token state SGLang keeps for every running request, and follows `--mamba-ssm-dtype`. Qwen3.8-Flash-Next NVFP4 failed to load on a 96 GB GPU before; its catalog entry now uses bf16 state.
- Goethe learns a model's real weight size from the main model plus its drafter (before, only the last loaded part counted), also when a start fails, and retries at a reduced context or concurrency instead of giving up. Loads on GPUs named with `--gpu` also shrink context and concurrency to fit instead of refusing.
- The static-pool limit is checked against free memory minus the CUDA context, as SGLang applies it, so the KV cache gets the tokens the plan promised.
- `goethe unload` waits up to 30 s for the GPU memory to be released, so an immediate `goethe load` no longer sees the old engine as a foreign process.
- A warm-up request runs before a model is reported RUNNING, so the first client request does not wait for first-use kernel builds.
- The gateway allows 100 requests per second (burst 200) and 512 open connections per client address, configurable with `GOETHE_GATEWAY_RATE_PER_IP` and `GOETHE_GATEWAY_CONN_PER_IP`; before, more than 32 concurrent streams from one machine got 429.
- `docs/registry.md`: what a registry entry must pass; `goethe/tests/load/mixed_load.py`: mixed prompt-length load test.

## 0.1.6 (2026-10-27)

- User guide restructured to match meshapplied.com/docs: what you can use it for, quick install, API compatibility (OpenAI, Anthropic and LiteLLM, with examples for each), CLI, models, sharing, and hardware, software, cloud and model compatibility. Examples use GLM-5.3 Flash.
- `goethe load` and `goethe start` say `Loading into VRAM...` while a model loads, instead of talking about kernel builds.
- CUDA 13 forward compatibility: data-center GPUs on NVIDIA drivers 535 to 579 (for example a CUDA 12.8 host) run Goethe without a driver upgrade. `goethe doctor` shows `<driver> with CUDA 13 forward compatibility`. GeForce and TITAN cards still need driver 580 or newer.

## 0.1.5 (2026-10-25)

- Goethe sees the GPU inside GPU containers (RunPod, Vast, Docker, Kubernetes): NVML is loaded as `libnvidia-ml.so.1`, the only name the NVIDIA container toolkit mounts; before, `goethe doctor` reported no hardware and nothing could load. Found on a RunPod RTX 3090.
- Run-time kernel builds find `ninja` from the py-env (its `bin` comes first on the engine's PATH); on machines without a system ninja every first load failed with `No such file or directory: 'ninja'`.
- RunPod (and other providers that set their variables on the container's main process) is detected from an SSH session too: the environment is completed from `/proc/1/environ`, so `goethe doctor` shows the pod's proxy URL and TCP endpoint.
- `goethe load` says when it reduced the context or the parallel requests to fit (`reduced to fit: context 65536 (asked 131072)`), and the installer's upgrade note names both builds again (`goethe --build-info`).
- A model whose first load spends minutes building kernels or capturing CUDA graphs without printing anything (Ada took 6 minutes for NVFP4) is no longer stopped as stalled: CPU work in the engine's processes counts as progress, and when goethed does stop an engine it logs why, which the failure report shows.
- Qwen3.5-family NVFP4 models (Qwen3.8-27B, Flash-Next, Qwen3.5-397B) load on Ampere, Ada and Hopper: SGLang enabled a Blackwell-only fused FP4 activation kernel even when Marlin serves the layers, failing with `Invalid backend: 80`; Goethe now sets `SGLANG_DISABLE_SILU_FP4_QUANT_FUSION=1` on GPUs whose NVFP4 path is Marlin.
- Checkpoints with packed FP4 experts (DeepSeek-V4/V4.1, MiMo) need extra memory while loading, when SGLang reorders each layer's experts: the memory spec carries this load peak (7 layers' worth, measured on a B200), the fit check requires weights plus peak, and a load that runs out of memory anyway says so and names the missing amount from PyTorch's message instead of a flat 4 GB guess. DeepSeek-V4-Flash on one B200 is now refused up front with the advice to split it across GPUs.
- Verified on RunPod, one GPU each, about $6 in all: RTX 3090 (8.6), RTX 4090 (8.9), A100 (8.0), H100 (9.0) and B200 (10.0), drivers 580.65 and 595.91, containers without systemd. Published and local installers, upgrade, `goethe doctor` (RunPod detected with its proxy URL), BF16, NVFP4 (Marlin on 8.x and 9.0, native on 10.0), the hybrid Qwen3.8-27B NVFP4 with 8 parallel requests and Gemma 4 26B with its pinned window pool, all answering through the gateway, each within 0.1 GB of its budget and within 2% of its planned KV tokens.
- Memory is sized the way SGLang allocates it, for every model, from its `config.json`: one memory spec per model (`memory_spec.rs`) that `goethe load`, `goethe models`, `goethe recommend` and catalog entries share. It covers the full-attention KV pool (K and V head sizes, per-GPU-generation layouts: DeepSeek-style sparse attention keeps FP8 latents on SM 10 and up, GLM-5.2 a 656-byte row on SM 12, the 132-byte index keys), MiniMax's sparse index cache, sliding-window pools (sized from what the running requests need and pinned with `--swa-full-tokens-ratio` and `--chunked-prefill-size`, instead of SGLang's default 80% share), linear-attention and Mamba state (5 slots per request on SGLang's extra-buffer models, 3 otherwise, plus the padding slot), DeepSeek-V4's compressed pools and per-request state, V4.1's window cap, and the request table. This fixes hybrid models being capped at a fraction of their parallel requests (16 slots allowed Qwen3.8-27B only 3 of 8).
- After each load Goethe learns how much the weights really take and how much the engine's CUDA context takes on that GPU type, and uses both on the next load, so the KV pools get the tokens they were planned for. Gemma 4 26B-A4B on an RTX PRO 6000: planned 262,144 full and 64,640 window tokens, SGLang allocated 260,585 and 64,255 (99.4%) at 68.95 GB against a 68.9 GB budget.
- Catalog: added MiMo-V2.6 Pro and Flash (RL), DeepSeek-V4.1-Flash-1017, DeepSeek-V4-Flash-0731, GLM-5.3-Flash, Ling-3.1-flash, Ling-3.0-flash, Qwen3.8-27B, Kimi-K2.6, Kimi-K2.7-Code, Nemotron-3.5-Super-VL-120B-A12B, Muse-Glimmer-30B and Gemma-4-26B-A4B, and re-measured Qwen3.8-Flash-Next, GLM-5.2 and MiniMax-M3. Each lists the GPU generations this SGLang build can run it on (for example DeepSeek-V4 and GLM-5.2 need Hopper or Blackwell, GLM-5.3-Flash data-center Blackwell, Ling-3.1 and Nemotron Ada or newer) and carries its memory spec; MiMo gets the MXFP4 MoE runner it needs. Removed the models above 1.2T parameters: Kimi-K3, its NVFP4 build, DeepSeek-V4-Pro-0813 and DeepSeek-V4-Pro-NVFP4. Muse-Spark-Open is not added: the bundled SGLang has no implementation of its architecture.

- `goethe --version` prints only the version (`goethe 0.1.4`). On a terminal it also checks the published version (2 s timeout) and, when a newer one exists, says so with `goethe update`. The commit and build date moved to `goethe --build-info`.
- `goethe configure api` (and step 3 of `goethe start`) asks whether you want to allow only specific IP addresses before showing the field to enter them: in VPN mode the whole VPN range is allowed unless you say yes, in public mode no client is added unless you say yes and name them.
- GPUs are named as `goethe gpu` lists them: `goethe load --model <id> --gpu gpu3`, or `--gpu gpu2 gpu3` to split a model across both (the number of GPUs is the tensor-parallel size), also on `install` and `config`. A count the model cannot be split over is refused with the counts that work, and when the named GPUs are too few the error names a `--gpu` list that fits. The older `--gpus 2,3` still works.
- Memory budgets are accurate for long contexts and hybrid models. The KV cache holds one request at the full context, or every parallel request at a quarter of it, instead of four full contexts. Hybrid models (Qwen3.5, Qwen3-Next and other linear-attention or Mamba models) budget their linear-attention state and pass the slot count to SGLang (`--max-mamba-cache-size`); before, SGLang gave about half of the KV budget to that state on its own.

Both ship in the signed package with Goethe's `LICENSE`, and the installer places them in `$GOETHE_HOME`. `goethe/packaging/third_party.py` regenerates them, and CI checks that they match `Cargo.lock` and `requirements.lock`.
- `goethe uninstall` now deletes the models Goethe installed, with the same rules as `goethe remove`: downloads and managed copies are deleted, models registered from a folder elsewhere or the Hugging Face cache lose only Goethe's links, and a folder of your own files inside the models directory is kept and named. The plan lists the models and the space they free, also with `--yes`. `--keep-models` keeps them; the old `--purge-models` still works.

## 0.1.3 (2026-10-25)

- The installer handles far more machines without stopping. For the GPU it tells apart: no GPU, no driver, a driver installed but not loaded (it runs `modprobe`, and names Secure Boot when that blocks it), a driver older than 580, NVIDIA's proprietary module on a Blackwell GPU (it switches to the open module), a GPU that did not start (it explains the power cycle), some GPUs not starting, and GPUs older than compute capability 8.0. - Right after a release, the package host's cache can serve old and new files side by side for up to 10 minutes, which made installs stop with `checksum mismatch`. A gcc newer than the bundled nvcc 13.0 supports (above 15) gets `-allow-unsupported-compiler`. `goethe doctor` has a compiler check, and a model that fails because of the compiler, missing GPU kernels or an old driver says so in its failure report.
- `goethe doctor` and `goethe start` recognise a GPU the driver did not start: the proprietary module on Blackwell, or a card that failed to initialise. `goethe start` explains such problems before the first step instead of failing on them. - Ada GPUs (compute capability 8.9: RTX 4090, RTX 6000 Ada, L40S, L4) are supported, on the same path as Ampere.

New keys are stored in `state.db` (owner-only) so they can be listed again; keys created before show only their first characters. In `goethe start` each screen starts clean, step 1 offers Install a new model, Serve an existing model and Run your own model, and step 3 lets you pick an existing key (listed by name and id) or name a new one (`[dev/my-app-name]`, default `dev`). The installer no longer starts goethed or turns on start at boot on a fresh install (an upgrade over a running goethed still applies the new binaries and keeps engines serving) and ends with `goethe start`.
- Every value you type is now a flag: `goethe install --model <id>`, `load --model`, `unload --model`, `remove --model`, `config --model`, `logs --model`, `scan --dir`, `key --create <name>` / `--revoke <id>`, `allowlist --add` / `--remove`, `alias --set <a> --model <id>` / `--remove`, `gpu --allow gpuN` / `--deny gpuN`, `gateway --bind`, and `registry validate --source`, `entry --repo`, `add --repo`. Plain `goethe key`, `allowlist`, `alias`, `gpu` and `gateway` list or show. New `goethe status` says whether Goethe is running, with the API address and the key names and ids; `goethe up` prints the same summary. `goethe domain` explains how to reach the API by a domain name (a DNS A record to the API's public or private address; Goethe no longer runs certbot) and `goethe domain --check <domain>` verifies it. `goethe key --help` shows the options for creating a key. Output is more spacious, with tables and indented commands marked with an arrow. `goethe recommend` and `goethe models` show what the allowed GPUs can run when empty (their total VRAM, per GPU) and group models by the VRAM they take; models that cannot be downloaded (manual or gated) are no longer listed. GPU tables show the PCIe capability (`PCIe 5 x16`) instead of the current/maximum link generation. In menus such as `goethe configure api` the selected row is marked with a light blue dot and shown in light blue (256-color 117, the same on every theme). Command examples use `deepseek-ai/DeepSeek-V4.1-Flash-1017`. Flags that name things take several at once, for example `goethe gpu --allow gpu0 gpu1`, `goethe key --revoke <id> <id>`, `goethe allowlist --add <cidr> <cidr>`, `goethe alias --remove`, `goethe unload --model` and `goethe remove --model`. A value typed without its flag (`goethe unload <id>`) or in the old verb form (`goethe gpu allow gpu0`, `goethe key revoke <id>`) prints the corrected command instead of a bare usage error.
- No CUDA toolkit install is needed: engines build run-time kernels with the toolkit bundled in the py-env (nvcc, crt, nvvm and cccl pinned to 13.0 to match the 13.0 runtime headers). Before each start Goethe adds the `lib64`, unversioned library and `libcuda.so` links that pip wheels leave out. `CUDA_HOME` or `CUDA_PATH` in goethed's environment or a card still wins.
- The installer offers to install the NVIDIA driver when a GPU has none or one older than 580. It asks first, uses `ubuntu-drivers` on Ubuntu or NVIDIA's CUDA repository on Debian and the RHEL family, then loads the driver or asks for a reboot. `GOETHE_INSTALL_DRIVER=1` installs without asking and `GOETHE_INSTALL_DRIVER=0` never installs. It never installs inside containers. A working driver is left alone.
- When the NVIDIA driver is unusable, `goethe doctor`, `goethe load` and the installer name the cause and the fix: no GPU attached to the VM or container, no driver loaded, driver older than 580, no `/dev/nvidia*`, or missing `libcuda.so.1`/`libnvidia-ml.so.1`. The installer reads the driver version from `/proc/driver/nvidia/version` when `nvidia-smi` is absent.
- Volta (7.0) and Turing (7.5) GPUs are recognised and named: `goethe gpu` marks them UNSUPPORTED with the reason, `goethe doctor` explains it, and placement never uses them.
- `goethe recommend` shows where each fitting model would load (GPUs, VRAM per GPU, context) and its download size, instead of one size column that looked like the VRAM need.

- GPU support covers Ampere (8.0, 8.6), Hopper (9.0) and data-center Blackwell (10.0, 10.3) next to consumer Blackwell (12.0, 12.1), from one architecture table. Machines with mixed GPU architectures work: placement only uses GPUs a model runs on, a tensor-parallel group never mixes architectures, `--gpus` sets that mix them are refused with the reason, and `goethe doctor` lists the architectures. Engines build run-time kernels for their own target (`TORCH_CUDA_ARCH_LIST`, `sm_90a`/`sm_100a` style) with one JIT cache per architecture.
